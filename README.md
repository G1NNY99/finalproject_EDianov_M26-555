# CurrencyTrade Hub

CurrencyTrade Hub — консольное приложение на Python для отслеживания валютных портфелей, симуляции покупки и продажи валют и получения валютных курсов из внешних API.

Проект разработан в рамках итогового задания Яндекс Практикума.

Торговые операции являются учебной симуляцией. Программа не совершает реальные финансовые операции.

**[Смотреть онлайн-демонстрацию на asciinema.org](https://asciinema.org/a/DaoSqrPaNZOp0UAc)**

## Возможности

- Регистрация и авторизация пользователей.
- Хранение хешей паролей с индивидуальными солями.
- Создание и просмотр валютных портфелей.
- Симуляция покупки валюты за USD.
- Симуляция продажи валюты с зачислением USD.
- Расчёт стоимости портфеля по актуальным курсам.
- Получение прямых, обратных и перекрёстных курсов.
- Загрузка криптовалютных курсов через CoinGecko.
- Загрузка фиатных курсов через ExchangeRate-API.
- Локальное кеширование курсов с TTL.
- Хранение истории валютных измерений.
- Фильтрация курсов по валюте, количеству и базовой валюте.
- Обработка ошибок внешних API.
- Логирование торговых операций и работы парсера.

- Python 3.12 и выше.

- requests — HTTP-запросы к внешним API.
- PrettyTable — табличный вывод данных.
- Ruff — форматирование и статический анализ.

## Архитектура проекта

Приложение разделено на четыре основных компонента.

### Core Service

Содержит модели пользователей, кошельков, портфелей, валют и бизнес-операции.

Основные функции:

- `register()`
- `login()`
- `show_portfolio()`
- `buy()`
- `sell()`
- `get_rate()`

При расчётах используются актуальные курсы из локального кеша Parser Service.

### Parser Service

Получает курсы валют из внешних источников, проверяет ответы API, сохраняет последние значения и историю измерений.

Основные компоненты:

- `ParserConfig` — настройки API и пути к данным.
- `BaseApiClient` — общий интерфейс API-клиентов.
- `CoinGeckoClient` — получение криптовалютных курсов.
- `ExchangeRateApiClient` — получение фиатных курсов.
- `RatesStorage` — хранение актуальных курсов и истории.
- `RatesUpdater` — координация обновления курсов.
- `rate_queries.py` (`RateQuote`, `RateListing`, `query_rates`) — проверка TTL, фильтрация курсов и пересчёт котировок без привязки к отображению в CLI.

### Infrastructure

Отвечает за загрузку конфигурации, работу с JSON-файлами и хранение данных.

`SettingsLoader` и `DatabaseManager` реализованы с использованием Singleton.

### CLI

Предоставляет интерактивный интерфейс для пользователей и команды управления Parser Service. CLI обрабатывает аргументы и отображает результаты в PrettyTable; проверку и пересчёт курсов выполняет `parser_service/rate_queries.py`.

## Настройка Parser Service

Для получения курсов используются два внешних источника:

- CoinGecko — курсы криптовалют.
- ExchangeRate-API — курсы фиатных валют.

### API-ключ ExchangeRate-API

Для работы ExchangeRate-API требуется персональный API-ключ.

Ключ необходимо получить на официальном сайте ExchangeRate-API и сохранить в переменной окружения:

```text
EXCHANGERATE_API_KEY
```

API-ключ нельзя размещать в исходном коде, README, `pyproject.toml` или файлах, публикуемых через Git.

### Настройка в Windows

Откройте свойства системы:

```cmd
SystemPropertiesAdvanced.exe
```

На вкладке «Дополнительно» выберите «Переменные среды».

В пользовательских переменных создайте:

- Имя: `EXCHANGERATE_API_KEY`
- Значение: персональный API-ключ.

После сохранения переменной необходимо запустить процесс CMD с обновлённым окружением.

Если существующее окно CMD не видит пользовательскую переменную, можно запустить вложенный CMD через PowerShell:

```cmd
powershell -NoProfile -Command "$env:EXCHANGERATE_API_KEY=[Environment]::GetEnvironmentVariable('EXCHANGERATE_API_KEY','User'); cmd /k"
```

В этом случае дальнейшие команды приложения необходимо выполнять во вложенном CMD.

Проверка загрузки ключа без отображения значения:

```cmd
uv run python -c "from valutatrade_hub.parser_service.config import ParserConfig; key=ParserConfig().exchangerate_api_key; print('API key loaded:', bool(key and key.strip()))"
```

Ожидаемый результат:

```text
API key loaded: True
```

Эта проверка подтверждает наличие ключа, но не его действительность на стороне API.

### CoinGecko

В конфигурации поддерживается необязательная переменная:

```text
COINGECKO_DEMO_API_KEY
```

При её наличии клиент передаёт Demo API-ключ через HTTP-заголовок.

Доступность запросов без ключа зависит от действующих правил и ограничений CoinGecko.

### Обновление курсов

Загрузка курсов из обоих источников:

```text
update-rates
```

Только CoinGecko:

```text
update-rates --source coingecko
```

Только ExchangeRate-API:

```text
update-rates --source exchangerate
```

Команда отображает количество полученных и обновлённых курсов, а также время последнего обновления.

Если один API недоступен, Parser Service может сохранить данные второго источника и сообщить о частичной ошибке.

Если оба источника не предоставили курсов, выводится сообщение об ошибке.

Первый успешный запуск обновления создаёт историю измерений в `data/exchange_rates.json`.

### Просмотр курсов

Все актуальные курсы:

```text
show-rates
```

Курс конкретной валюты:

```text
show-rates --currency BTC
```

Две самые дорогие криптовалюты:

```text
show-rates --top 2
```

Курсы относительно EUR:

```text
show-rates --base EUR
```

Фильтры можно комбинировать, например:

```text
show-rates --top 2 --base EUR
```

Команда читает локальный кеш и не выполняет HTTP-запросы.

Устаревшие или некорректные котировки исключаются из таблицы.

### Получение конкретного курса

```text
get-rate --from EUR --to USD
get-rate --from USD --to BTC
get-rate --from BTC --to EUR
```

Программа рассчитывает прямой и обратный курсы по актуальным данным кеша.

Поддерживаются перекрёстные курсы через USD.

Если необходимый курс отсутствует или устарел, программа предлагает выполнить `update-rates`.

### Просмотр портфеля

```text
show-portfolio
show-portfolio --base EUR
```

Стоимость кошельков и итоговая стоимость портфеля рассчитываются по актуальным валютным курсам.

### Покупка валюты

```text
buy --currency EUR --amount 10
buy --currency BTC --amount 0.01
```

Сумма покупки рассчитывается в USD по актуальному курсу.

Если USD-баланса недостаточно, операция отклоняется с `InsufficientFundsError`.

### Продажа валюты

```text
sell --currency EUR --amount 5
sell --currency BTC --amount 0.01
```

Указанная сумма списывается с валютного кошелька, а выручка зачисляется в USD.

Если валюты недостаточно, операция отклоняется.

### Ограничения торговой симуляции

Регистрация создаёт пустой портфель.

Команда пополнения начального USD-баланса в текущей реализации отсутствует. Поэтому покупка сразу после регистрации не может завершиться успешно без предварительно подготовленного тестового баланса.

В изолированных функциональных тестах начальный баланс задаётся во временных JSON-данных.

Примеры `buy` и `sell` показывают синтаксис команд, а не гарантируют успешную сделку в пустом портфеле.

Торговая модель поддерживает USD, EUR, RUB, BTC и ETH.

Parser Service дополнительно получает курсы GBP и SOL, которые можно просматривать через `show-rates`. Торговые операции с этими дополнительными валютами пока не реализованы.

## Хранение данных

### users.json

Содержит пользователей, идентификаторы, хеши паролей, соли и даты регистрации.

Пароли в открытом виде не сохраняются.

### portfolios.json

Содержит пользовательские портфели и балансы валютных кошельков.

### rates.json

Хранит последние полученные курсы в структуре `pairs`.

Упрощённый пример:

```json
{
  "pairs": {
    "EUR_USD": {
      "rate": 1.25,
      "updated_at": "2026-10-19T12:00:00Z",
      "source": "ExchangeRate-API"
    }
  },
  "last_refresh": "2026-10-19T12:00:00Z"
}
```

Значения в примере учебные.

### exchange_rates.json

Хранит историю уникальных измерений.

Каждая запись содержит:

- `id` — идентификатор измерения.
- `from_currency` — исходная валюта.
- `to_currency` — целевая валюта.
- `rate` — курс.
- `timestamp` — время измерения.
- `source` — источник данных.
- `meta` — дополнительные метаданные.

Повторные измерения с одинаковыми валютной парой и временем не дублируются.

Более старое измерение может сохраняться в истории, но не перезаписывает более актуальный курс.

## Кеширование и TTL

Значение TTL задаётся параметром:

```toml
rates_ttl_seconds = 300
```

Настройка находится в `pyproject.toml` в разделе `[tool.valutatrade]`.

300 секунд соответствуют пяти минутам.

При запросе курса проверяются:

- Наличие валютной пары.
- Корректность числового значения.
- Положительность курса.
- Наличие времени обновления.
- Соответствие времени обновления TTL.

Если курс отсутствует или устарел, `get-rate`, торговые операции и оценка непустого портфеля могут завершиться ошибкой.

Для получения новых данных необходимо выполнить:

```text
update-rates
```

Автоматическое обновление по расписанию в текущей версии не настроено. Доступно ручное обновление через CLI.

## Обработка ошибок

В проекте реализованы пользовательские исключения:

- `InsufficientFundsError` — недостаточно средств.
- `CurrencyNotFoundError` — неизвестный код валюты.
- `ApiRequestError` — ошибка API или отсутствие пригодного курса.

API-клиенты обрабатывают сетевые ошибки, превышение времени ожидания, HTTP-ошибки, неправильный JSON и некорректные курсы.

Торговые операции не используют демонстрационную цену при отсутствии актуальной котировки.
